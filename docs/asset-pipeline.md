# Asset identity and dependency tracking (Phases 3.5 and 5.4)

This document specifies the asset-pipeline contracts implemented by `hycel-assets`. It establishes source hashing, per-resource import provenance, cache/reimport decisions, and deterministic scene/resource dependency reports. Phase 5.4 adds authored animation clips as reusable versioned resources and tracks their texture dependencies. It does not yet decode image/audio formats or run native import tools.

## Separate identity layers

- A resource descriptor's UUID is the stable authored identity. Renaming or editing the source does not change this UUID.
- `ContentHash` is SHA-256 over the exact source bytes. Paths, timestamps, directory enumeration order, and file metadata are excluded.
- `ImportFingerprint` is a separately versioned SHA-256 digest over a domain/version tag, source digest, importer kind, importer/tool version, and canonical JSON import settings. Resource UUID and path are not part of that digest.
- Cache records use a **hybrid identity**: generated entries live under `.hycel/imports/<resource-uuid>/<fingerprint>/`. The UUID keeps project resources distinct; the fingerprint invalidates entries when source bytes, settings, importer, or tool version change. Cache objects are not shared across resource UUIDs in this first design.

Importers must behave as deterministic functions of the bytes and settings represented by the fingerprint plus their recorded version. They must not read undeclared neighboring files, environment state, clocks, random sources, or host-dependent paths. Any future external inputs/dependencies or target-specific output must be explicitly declared and added to a versioned fingerprint contract before that behavior ships. Platform-independent imported intermediates are preferred; target-specific packaging is a later build step.

## Source hashing and safety

`hash_source_file(project_root, relative_path, max_bytes)` resolves the existing project-relative path with `hycel-project` containment and symlink checks, requires a regular file, and streams it with bounded memory. The caller provides a maximum byte count; oversize files fail with a typed error before a digest is returned. Hashing uses the complete bytes, not an mtime/size shortcut. Empty files have the SHA-256 empty-input digest. A later content change is detected by recomputing the digest. The read is not a filesystem snapshot or race-resistant file handle: callers must exclude concurrent source writes and project path-component changes (including renames/symlink replacement) while hashing/importing. The canonical-path containment check is point-in-time and does not defend against a hostile process concurrently replacing the tree.

## Import record and reimport policy

The strict, version-1 JSON `ImportRecord` snapshots resource UUID, source path, source SHA-256, importer kind and version, exact import settings, and the computed fingerprint. It is bounded to 1 MiB when read, rejects unknown fields, validates IDs/paths/digests, and recomputes the fingerprint before accepting a record. It is derived metadata; authored descriptor settings remain the source of truth.

`plan_reimport` compares a validated previous record with the desired record, without timestamps:

| Difference | Decision |
| --- | --- |
| No prior record | Import (`FirstImport`) |
| Resource UUID changed | Import (`ResourceIdentityChanged`) |
| Source content digest changed | Import (`SourceChanged`) |
| Importer kind/version changed | Import (`ImporterChanged`) |
| Import settings changed | Import (`SettingsChanged`) |
| Fingerprint contract changed | Import (`FingerprintChanged`) |
| Same import inputs, source path changed | Update metadata only; existing output remains valid |
| Same inputs and path | Reuse cached output |

Changing only the source path does not alter generated bytes under the importer-purity contract. The record still updates so dependency reports show the current authored path. Old fingerprint directories are not deleted automatically; cache cleanup needs a later explicit, recoverable policy.

## Dependency report

`AssetDependencyReport` is a deterministic schema-2 snapshot with resources keyed by UUID and scenes keyed by scene UUID. It reports each resource's descriptor file, importer kind/source path, each scene's direct resource UUID dependencies discovered from component fields explicitly declared as references, and animation-resource-to-texture edges from validated clip frames. Scene and resource edges are emitted in lexical UUID order. Missing/wrong-kind resource dependencies, missing animation clip sources, and duplicate scene/resource identities are errors; normal project validation should run first for detailed source diagnostics.

Animation clips are strict schema-1 JSON source documents referenced by `animation` resource descriptors. Their frame texture references are stable resource UUIDs and tick durations are positive bounded integers; renderer-local texture handles are never authored. The CLI validates scene `hycel.animation.clip_id` references against animation-kind descriptors and validates every clip frame against a texture-kind descriptor. These resource dependency edges are direct-only; implicit filesystem discovery is forbidden.

## Generated data and failure policy

Import records and future imported outputs belong below `.hycel/`, never over `src/`, `assets/`, `scenes/`, descriptors, or source files. A future importer runner must stage outputs, validate them, and commit them transactionally; cancellation or failure must retain the previous valid cache and authored data. Cache pruning is not part of the current API.

## Dependency boundary

`hycel-assets` depends on `hycel-project` for validated descriptors, scene references, and path containment; the dependency direction is one-way. SHA-256 reuses workspace dependency `sha2`, already reviewed in [ADR 0002](adr/0002-replay-format-and-state-hash.md). `serde`/`serde_json` are existing reviewed workspace dependencies. This phase adds no new third-party package.

See [`scene-format.md`](scene-format.md) for resource descriptor inputs and [`project-format.md`](project-format.md) for per-format schema/migration status.
